# Flutify 0.12

今天我很高兴，所以这一版不再是 beta，是 Flutify 的第一个正式版。应用版本为 `0.0.12+12`。

本版大幅降低了歌词播放页的 GPU 占用，观感保持不变，并新增省电模式与帧率上限，欢迎测试并反馈。

## 歌词播放页性能

- 流动封面背景改为在 1/8 分辨率的离屏画布上完成大半径模糊，再平滑放大铺满。逐像素对比，与原实现的平均差异约 0.4/255，最大 3/255，肉眼不可分。
- 沉浸式歌词页中，下方只有流动背景、不会有歌词滑过的玻璃（宽屏左栏控制台、歌名旁按钮、左上角胶囊），不再每帧复制并模糊下方画面；会有歌词滑过的玻璃保持真实模糊。
- 过长的歌名在每轮滚动前静止的 4 秒内不再逐帧重绘整个窗口。
- 每一行歌词使用独立图层：跑马灯、当前句等别处在动时，已模糊好的歌词行直接复用缓存，不再每帧重新模糊。
- 在测试设备上，背景加 5 块玻璃的组合由约 20% 降至约 7%~10%（按 Windows GPU 计数器测量）。暂停播放时背景停止流动，GPU 占用接近 0。

## 新增：省电模式与帧率上限

位于“设置 → 动效”：

- **省电模式**（默认关闭）：玻璃不再实时模糊下方画面，改为半透明磨砂底；歌词页流动背景静止，保留封面配色。歌词滚动、模糊与当前句动效全部保留。测试设备上，歌词页每帧渲染耗时约降低三分之一。
- **帧率上限**（默认跟随屏幕）：提供 165 / 144 / 120 / 90 / 60 档位，以及 30~240 fps 逐帧可调的滑杆。对整个窗口生效，动画速度不变，只是出帧更少；高刷屏上调低可明显减少 GPU 占用。

### 与 Spotify 官方客户端对比

同一台 Windows 设备、两者同时运行时的任务管理器截图：

![Flutify 与 Spotify 官方客户端的资源占用对比](https://raw.githubusercontent.com/is-hp-is-mad/Flutify/v0.12/docs/releases/assets/v0.12-task-manager.png)

- **CPU**：与官方客户端差距不大，日常使用中最多相差 7% 左右；截图时 Flutify 为 3.8%，官方为 7.5%。
- **内存**：碾压官方。Flutify 154 MB，加上播放用的 WebView2 进程约 71 MB，合计约 225 MB；官方客户端 531 MB。
- **GPU**：较上一版显著降低，歌词播放页从约 50% 降至约 27%~30%（165Hz 屏幕、全部效果开启）。官方客户端没有流动背景和液态玻璃效果，占用仍低于 Flutify；对占用敏感时可开启省电模式或调低帧率上限。

## 下载

- Windows x64 / ARM64：安装版 `*-setup.exe` 与便携版 `.zip`。
- Android：arm64-v8a、armeabi-v7a、x86_64 和通用 APK，沿用此前的固定签名，可直接覆盖安装。
- macOS 12.0 及以上：`Flutify-v0.12-macos.zip`，解压后将 `Flutify.app` 放入应用程序目录。未做 Developer ID 签名和 Apple 公证，首次打开可能需要在系统设置的“隐私与安全性”中允许打开。
- 共九个安装包，校验和见 `SHA256SUMS.txt`。

## 已知问题

- 从 v0.09 或更早版本升级时，旧版 Windows 更新器可能仍会失败；请手动运行新版安装包。
- Windows 原生 Widevine 许可证 HTTP 403 问题仍未解决；x64 保留实验性原生路径及加载失败回退，ARM64 继续使用 WebView2。
- macOS 搜索框上半部分在部分机器上仍可能触发窗口拖动（[#18](https://github.com/is-hp-is-mad/Flutify/issues/18)），原生层修复见 [#19](https://github.com/is-hp-is-mad/Flutify/pull/19)，待实机测试后合并。
- macOS 仍需不同机型、系统版本与账号的实机验证。
