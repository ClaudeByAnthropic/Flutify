# Android v0.04-beta 启动与覆盖升级调查

用户报告：小米 17 Pro MAX、Android 16、澎湃 OS 3，打开后白屏且不闪退。

## 已复现的启动缺陷

v0.04 在 `runApp` 前初始化缓存；原来的目录检查沿路径一直检查到文件系统根，拒绝任何符号链接。系统提供的应用目录可能经过目录别名（如 Android 的 `/data/user/0`、macOS 的 `/var`），因此即使默认缓存目录本身正常，也会触发异常。回退默认目录会再次失败，界面尚未创建，留下原生启动背景。

回归测试使用真实目录链接（Windows junction / POSIX symlink），已验证旧代码失败。修复仅规范化系统提供的应用数据根目录和旧图片缓存的系统临时根目录；缓存子目录及自定义位置继续拒绝链接。测试覆盖初始化、迁移、清理及链接保护。

启动现在先绘制界面，再初始化服务，记录各阶段；异常显示失败阶段，等待超过 20 秒提供复制诊断信息。等待较久的操作仍可完成，不会重复初始化服务。

这证明了一条会导致白屏的代码路径，尚无上述手机的 logcat 或修复后实机结果，不能据此断言已确认该设备的唯一原因。原版 ARM64 APK 所有原生库的 ELF 段与 ZIP 偏移均满足 16KB 对齐，没有发现该项问题。

## 发布 APK 的签名

直接提取 GitHub 发布 APK 的 v2 签名证书，三版包名均为 `com.flutify.music.flutify_app`：

| ARM64 APK | versionName | versionCode | 证书 SHA-256 |
| --- | --- | --- | --- |
| v0.02-beta | 0.0.1 | 2001 | `2c35f5b0d75c9a055ac26bf14237a8d6e8017866b04bda2c015dd2ec61a86353` |
| v0.03-beta | 0.0.1 | 2001 | `00c4822ccf656c577883b05463bd14f6f5cd34e2d21d504f1377e020762ede7c` |
| v0.04-beta 原版 | 0.0.4 | 1322001 | `f342b46d13f500863b6ed4987ae78e5e57d6f8f53690e6e79fa33f17871f2715` |

0.02、0.03 与 0.04 的签名不同，且没有签名轮换证明，不能直接覆盖升级。提高版本号无法解决签名不匹配。不要为升级盲目卸载，卸载通常会删除应用数据。

0.04 的构建已使用仓库 Secret 中的固定 beta 密钥，缺少密钥时构建失败。CI 使用 `apksigner verify` 验证所有 APK 和预期证书，同时检查版本号。本次重建必须保持上述 0.04 证书并提高 versionCode，才能覆盖原版 0.04 并保留数据；发布后还需比对实际新包。

## 真机复测

1. 原版 0.04 用户直接安装重建后的 ARM64 APK，确认系统允许更新且登录和设置保留。
2. 强制停止后冷启动，确认进入主页；测试离线启动。
3. 若停在启动提示超过 20 秒或显示启动失败，复制诊断信息反馈具体阶段。若连 Flutify 启动提示都不出现，应采集 `adb logcat` 排查 Dart 运行前的引擎或原生问题。
4. 验证播放、通知栏媒体控制、缓存读写与清理。
